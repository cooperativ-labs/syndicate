# How to Use Generated GraphQL Types from `gql/` Folder

This guide explains how to use the TypeScript types generated by GraphQL Code Generator in the `gql/` folder.

## Quick Overview

Your codegen setup (using the `client` preset) generates:

- **Type definitions** in `gql/graphql.ts` - All GraphQL types
- **Query/Mutation helpers** in `gql/gql.ts` - The `graphql()` function
- **Fragment helpers** in `gql/fragment-masking.ts` - Fragment utilities

## Usage Patterns

### 1. **Using the `graphql` Function for Type-Safe Queries**

Instead of using `gql` from Apollo, use the generated `graphql` function:

```typescript
import { graphql } from '@gql/index';
import { useQuery } from '@apollo/client';

// Define your query - this is type-safe!
const GET_ORGANIZATION_QUERY = graphql(`
  query GetOrganization($id: UUID!) {
    organizationsCollection(filter: { id: { eq: $id } }, first: 1) {
      edges {
        node {
          id
          name
          slug
          logo
          brand_color
        }
      }
    }
  }
`);

// Use in a component
function OrganizationPage({ orgId }: { orgId: string }) {
  const { data, loading, error } = useQuery(GET_ORGANIZATION_QUERY, {
    variables: { id: orgId }
  });

  // TypeScript knows the exact shape of `data`!
  if (data?.organizationsCollection?.edges[0]?.node) {
    const org = data.organizationsCollection.edges[0].node;
    return <div>{org.name}</div>; // Fully typed!
  }
  return null;
}
```

### 2. **Using Generated Types Directly**

Import types from `gql/graphql.ts` for function parameters, return types, etc.:

```typescript
import type { Organizations, Query, Mutation } from '@gql/graphql';

// Use in function signatures
function processOrganization(org: Organizations): string {
  return org.name || 'Unnamed';
}

// Use query input types
function buildOrganizationFilter(filter: OrganizationsFilter): OrganizationsFilter {
  return filter;
}

// Use mutation types
function createOrganizationInput(input: OrganizationsInsertInput): OrganizationsInsertInput {
  return input;
}
```

### 3. **Type-Safe Mutations**

```typescript
import { graphql } from '@gql/index';
import { useMutation } from '@apollo/client';

const CREATE_ORGANIZATION_MUTATION = graphql(`
  mutation CreateOrganization(
    $name: String!
    $slug: String
    $logo: String
  ) {
    insertIntoorganizationsCollection(objects: [{
      name: $name
      slug: $slug
      logo: $logo
    }]) {
      records {
        id
        name
        slug
      }
    }
  }
`);

function CreateOrgForm() {
  const [createOrganization, { loading }] = useMutation(CREATE_ORGANIZATION_MUTATION);

  const handleSubmit = (name: string, slug: string) => {
    createOrganization({
      variables: {
        name,
        slug,
        // TypeScript will error if required fields are missing
      }
    });
  };

  return <form onSubmit={handleSubmit}>...</form>;
}
```

### 4. **Using DocumentType Helper**

Get the return type of a query automatically:

```typescript
import { graphql, DocumentType } from '@gql/index';

const GET_ORGANIZATION_QUERY = graphql(`
  query GetOrganization($id: UUID!) {
    organizationsCollection(filter: { id: { eq: $id } }, first: 1) {
      edges {
        node {
          id
          name
        }
      }
    }
  }
`);

// Automatically extracts the query return type
type OrganizationQueryResult = DocumentType<typeof GET_ORGANIZATION_QUERY>;
```

### 5. **Using Fragment Types**

If you create fragments, you can use them like this:

```typescript
import { graphql, FragmentType, useFragment } from '@gql/index';

// Define a fragment
const OrganizationFieldsFragment = graphql(`
  fragment OrganizationFields on organizations {
    id
    name
    slug
    logo
    brand_color
  }
`);

// Use fragment in a query
const GET_ORGANIZATIONS_QUERY = graphql(`
  query GetOrganizations {
    organizationsCollection(first: 10) {
      edges {
        node {
          ...OrganizationFields
        }
      }
    }
  }
`);

function OrganizationCard({
  organization
}: {
  organization: FragmentType<typeof OrganizationFieldsFragment>
}) {
  // Unwrap the fragment to get the actual data type
  const org = useFragment(OrganizationFieldsFragment, organization);

  return <div>{org.name}</div>;
}
```

### 6. **Using Enum Types**

```typescript
import type { Currency_Code, Organization_Permission_Type } from '@gql/graphql';

function handleCurrency(currency: Currency_Code) {
  switch (currency) {
    case 'USD':
      return '$';
    case 'EUR':
      return '€';
    // TypeScript will ensure all cases are covered
  }
}

// Type-safe enum in filters
const filter: OrganizationsFilter = {
  // TypeScript knows valid fields and enum values
};
```

### 7. **Using Filter Types**

```typescript
import type { OrganizationsFilter, UuidFilter, StringFilter } from '@gql/graphql';

// Build type-safe filters
function buildFilter(orgId: string, name?: string): OrganizationsFilter {
  const filter: OrganizationsFilter = {
    id: { eq: orgId } as UuidFilter
  };

  if (name) {
    filter.name = { ilike: `%${name}%` } as StringFilter;
  }

  return filter;
}
```

## Migration Example

If you have existing queries using plain `gql`, migrate them like this:

**Before:**

```typescript
import { gql } from '@apollo/client';

const GET_ORG = gql`
  query GetOrg($id: UUID!) {
    organizationsCollection(filter: { id: { eq: $id } }) {
      edges {
        node {
          id
          name
        }
      }
    }
  }
`;
```

**After (with types):**

```typescript
import { graphql } from '@gql/index';

const GET_ORG = graphql(`
  query GetOrg($id: UUID!) {
    organizationsCollection(filter: { id: { eq: $id } }) {
      edges {
        node {
          id
          name
        }
      }
    }
  }
`);
```

The only differences:

1. Import `graphql` from `@gql/index` instead of `gql` from Apollo
2. Remove the backtick template tag syntax (just use regular template literals)
3. Get full type safety automatically!

## Regenerating Types

After changing your GraphQL schema or queries, regenerate types:

```bash
yarn generate
# or if you have a script:
yarn codegen
```

## Tips

1. **IDE Autocomplete**: The generated types provide full autocomplete for query fields
2. **Type Safety**: TypeScript will catch typos in field names and missing required variables
3. **Refactoring**: Changing a query will automatically update types after regeneration
4. **Path Alias**: Your `tsconfig.json` includes `@gql/*` path mapping, so use `@gql/index` or `@gql/graphql`
